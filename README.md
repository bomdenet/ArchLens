# ArchLens

**ArchLens** is an open-source, agent-friendly C#/.NET architecture analysis engine built on **Roslyn**, exposing compact, structured tools over **MCP (Model Context Protocol)** and a **CLI**.

It gives AI coding agents architectural visibility (similar to NDepend, but open-source, extensible, and designed for LLM context budgets) while also serving as a deterministic CI/CD architecture gate.

---

## Features (v0.8)

- **Dual Extraction Backends behind `ICodeGraphExtractor`:**
  - **Roslyn (`ArchLens.Extraction.Roslyn`)** — full semantic analysis for `.slnx`, `.sln`, and `.csproj`, with **Blazor/Razor (`.razor`)** and **XAML (`.xaml`/`.axaml`)** support, automatic exclusion of generated code (`obj/`, `.g.cs`, `<auto-generated>`, `[GeneratedCode]`, `JsonSerializerContext`) from metrics, target framework selection (`--tfm`), and **incremental `Document`-level updates inside warm `MSBuildWorkspace` sessions**.
  - **IL + Portable PDB (`ArchLens.Extraction.Metadata`)** — fast compiled `.dll` + `.pdb` reader built on `System.Reflection.Metadata` (`--backend il` / `backend: "il"`), 10-30x faster for overviews and dependency maps (use Roslyn for CI gates).
- **Three-Tier Caching & Auto-Invalidation (MCP + CLI):** in-memory cache with `FileSystemWatcher` + mtime, warm Roslyn `Document` updates, and a **persistent SQLite graph cache (`SqliteGraphCache`)** shared across MCP and CLI (`archlens batch`, `--no-cache`, `--refresh`).
- **Dynamic Plugins (`.archlens/plugins/*.dll`):** load custom `IArchitectureRule`, `ICustomMetricCalculator`, and `IEntryPointDetector` implementations inside isolated collectible `AssemblyLoadContext` instances without locking DLL files (opt-in via `--allow-plugins` or `ARCHLENS_ALLOW_PLUGINS=1`).
- **SQL over Graph (`query` / `archlens query`):** projects the code graph into in-memory SQLite (`nodes`, `edges`, `metrics`, `projects`, `di_registrations`, `analyzer_diagnostics`, `custom_metrics`, `schema_info`) with multi-layer read-only protection (`sqlite3_set_authorizer`, `PRAGMA query_only = ON`, SQL validation, timeout), column suggestions on errors, and `--schema` / `includeSchema: true`.
- **Architecture Presets & Custom Layer Mapping (`archlens presets` / `archlens init --preset ...`):** built-in rule packs for `clean-architecture`, `vertical-slice`, `modular-monolith`, and `ddd`, supporting custom `layers:` namespace mappings in `.archlens.yaml`.
- **Cycle Detection (Tarjan SCC):** directed cycle paths with concrete type-edge locations at project, namespace, type, and method scope; skips EF Core migrations and pure parent-child namespace pairs (`A <-> A.Sub`) by default while reporting suppressed cycle counts transparently.
- **God Class Detection & Metrics:** $C_a$, $C_e$, Instability ($I$), Abstractness ($A$), Distance from Main Sequence ($D$), cyclomatic and **cognitive complexity**, **LCOM4**, LOC, constructor parameter counts, composite **`god_class`** rules & hotspot ranking (`--by god_class`), and custom plugin metrics.
- **Dead Code & Unreferenced Symbols (`dead_code` / `archlens dead-code`):** reachability BFS with `auto | app | lib | strict` profiles, automatic exclusion of test-support projects (`*.Tests.Support`), built-in entry-point detectors (`Program.Main`, Blazor `@page`/Layout, WPF/XAML, ASP.NET Controllers/Minimal APIs, MediatR/MassTransit, xUnit/NUnit/MSTest, DI registrations, library public APIs), and **`acknowledge:`** entries in `.archlens.yaml`.
- **DI Graph Analysis (`di_analysis` / `archlens di`):** parses `IServiceCollection` registrations (`AddSingleton`/`AddScoped`/`AddTransient`/`AddHostedService`), compact lifetime/project summaries, filtering (`lifetime`, `project`, `serviceType`, `onlyCaptive`, `onlyUnregistered`), direct and transitive *captive dependency* detection, and single-implementation interface tracking.
- **Roslyn Analyzer Aggregation (`analyzers` / `archlens analyzers`):** runs `Microsoft.CodeAnalysis.NetAnalyzers` / `Roslynator` filtered by category and severity (defaults to `minSeverity=warning`, reporting hidden lower-severity counts or missing analyzer references explicitly, while skipping generated files and EF migrations).
- **Blast Radius Analysis (`impact`):** transitive impact analysis excluding DI registrations and tests by default, with automatic summary mode in MCP when fan-in > 20 (`--summary-only` in CLI).
- **Diagrams, HTML Reports, SARIF 2.1.0 & Baselines:** exports **Mermaid**, **Graphviz DOT**, **Structurizr DSL**, standalone **HTML** (with DSM and trend SVG), **SARIF 2.1.0**, and persistent `.archlens-baseline.json` diffs (`archlens baseline` / `archlens diff --fail-on-new-errors`).
- **MCP Prompts & Resources:** built-in prompts (`audit-architecture`, `plan-layer-refactoring`, `review-pr-architecture`, `investigate-dead-code`) and resources (`archlens://schema/sql`, `archlens://presets`, `archlens://rules/reference`).
- **Agent Feedback Loop (`give_feedback`):** agents report wrong or confusing tool behavior, missing capabilities and performance problems in ArchLens itself; reports are sanitized (credentials and user paths removed), deduplicated by fingerprint, rate-limited, and delivered — by default to the shared bomdenet intake at `https://feedback.bomdenet.com/api/feedback` (no token needed), or directly to GitHub Issues with a PAT, or through `ARCHLENS_FEEDBACK_URL` — with a local outbox that retries at the next server start. `ARCHLENS_FEEDBACK_MODE=off` disables reporting.
- **Two Thin Adapters (`.NET Global Tool`):** `ArchLens.Mcp` (`archlens-mcp`) and `ArchLens.Cli` (`archlens`).

## Quick Start

### Prerequisites
- [.NET 10 SDK](https://dotnet.microsoft.com/)

### Install as a .NET Global Tool
```bash
dotnet tool install -g ArchLens.Cli
dotnet tool install -g ArchLens.Mcp
```

Or pack and install locally from source:
```bash
dotnet pack src/ArchLens.Cli -c Release -o artifacts/nupkgs
dotnet pack src/ArchLens.Mcp -c Release -o artifacts/nupkgs
dotnet tool install -g --add-source artifacts/nupkgs ArchLens.Cli
dotnet tool install -g --add-source artifacts/nupkgs ArchLens.Mcp
```

### Build & Test
```bash
dotnet build ArchLens.slnx
dotnet test ArchLens.slnx
```

### CLI Examples (Self-Check on ArchLens)
```bash
dotnet run --project src/ArchLens.Cli -- overview .
dotnet run --project src/ArchLens.Cli -- check .
dotnet run --project src/ArchLens.Cli -- hotspots . --by god_class --top 10
dotnet run --project src/ArchLens.Cli -- graph . --scope namespace
dotnet run --project src/ArchLens.Cli -- impact . CodeGraph --summary-only
```

### Configure the MCP Server
Add ArchLens to your MCP client configuration (Claude Code, Cursor, Antigravity, VS Code Copilot, etc.):

```json
{
  "mcpServers": {
    "archlens": {
      "command": "archlens-mcp"
    }
  }
}
```
> Or run directly from source: `dotnet run --project src/ArchLens.Mcp/ArchLens.Mcp.csproj -c Release`.
>
> **Feedback (optional):** reports go to the shared intake `https://feedback.bomdenet.com/api/feedback` by default and need no token; set `ARCHLENS_FEEDBACK_MODE=off` to disable reporting, `ARCHLENS_FEEDBACK_MODE=outbox` to only queue locally, or `ARCHLENS_FEEDBACK_TOKEN` (fine-grained PAT with `issues:write`) to file GitHub issues directly. See [docs/mcp-tools.md](docs/mcp-tools.md#feedback-delivery-give_feedback).
